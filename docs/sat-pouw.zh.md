# SAT-PoUW — 以 SAT 求解为工作量的有用工作量证明

**核心主张**：前两个方案（NarrowNet / PoRT）都在**人为构造**「GPU 不擅长」的特性。
而 SAT 求解**天生就是那个样子**——并且它的产出有真实工业价值。

> **状态：设计稿，核心假设未经实测。** 最关键的一条（SAT 求解器的多线程扩展效率）
> 尚未验证，这是可以一票否决整个方案的实验。见 §9。

---

## 1. 为什么 PoUW 是加密圈的坟场

失败项目一大堆，根因是六条要求互相打架：

| PoW 需要 | 真实有用的问题通常 |
|---|---|
| 难度可精确调节 | ❌ 难度不可控，且分布重尾 |
| 验证远快于求解 | ❌ 很多问题验证和求解一样贵 |
| 题目无限供应 | ❌ 题目有限，且需要有人出题 → **中心化** |
| 不可预计算 | ❌ 题目提前公开就能预先算好 |
| 同等硬件算力等价 | ❌ 算法差异导致赢家通吃 |
| 结果唯一/确定 | ❌ 优化类问题没有"标准答案" |

**筛选标准收敛成一句话：**

> **求解是 NP 难 / 指数级，验证是 O(n) 线性。**

满足这条的问题不多。

---

## 2. 为什么选 SAT

给定合取范式（CNF）布尔公式，找一组变量赋值使其为真。

| 要求 | SAT 的表现 |
|---|---|
| **验证极快** | ✅ **代入检查所有子句，O(n)**。求解 NP 完全，验证线性 —— 不对称性是所有候选里最好的 |
| **天生反 GPU** | ✅ CDCL 求解器是公认的「不规则负载」：数据相关分支密集、指针追逐（watched literals）、冲突学习带来强串行依赖。学术界搞了二十年 GPU SAT，基本失败 |
| **天生小机器友好** | ⚠️ 子句数据库典型 2–8 MB，**落在我们实测的缓存争用甜点区**（≥2MB 时 4 线程即损失 32–38%）—— **但这一条对 SAT 求解器尚未实测** |
| **真实需求** | ✅ 硬件验证、软件形式化验证、调度规划、密码分析、生物信息 —— 工业界日常刚需 |
| **题目无限** | ✅ 可由区块头确定性生成合成实例 |
| UNSAT 怎么办 | ❌ 证明「无解」需要 DRAT 归结证明，可能指数级大 —— **本方案只用 SAT 实例，不要求判定 UNSAT** |

**关键观察**：NarrowNet 里用 FP64、指针追逐、串行链**人为制造**的那些「GPU 不适感」，SAT 求解器**天然全都有**。

## 3. 两层协议

单靠真实题目会中心化（谁出题谁掌权），单靠合成题目又没有效用。分层解决：

### 第一层 — 共识层（合成实例）

```
instance ← generate_3SAT( H(prev_block_hash ‖ miner_id ‖ nonce) )
assign   ← solve(instance)                     # ← 挖矿工作
if assign ≠ ⊥ and H(instance ‖ assign) < TARGET:
    broadcast_block(nonce, assign)
```

**作用**：难度可控、不可预测、无限供应、无需任何人出题 → **共识安全不依赖外部**。

**验证**（任何节点，毫秒级）：

```
verify(blk):
    instance ← generate_3SAT(H(prev ‖ blk.miner_id ‖ blk.nonce))   # 确定性重建
    assert satisfies(instance, blk.assign)                          # O(n) 代入检查
    assert H(instance ‖ blk.assign) < TARGET
```

### 第二层 — 效用层（真实实例市场）

```
用户提交真实 CNF + 悬赏 → 矿工用同一套求解器顺手解 → 任何人 O(n) 验证 → 领赏
```

**作用**：产生真实价值，**但完全不影响共识安全**——即使效用层被操纵或停摆，链照常运行。

**两层共用同一套求解器基础设施。** 矿工为竞争而优化 CPU SAT 求解器，这本身就是有价值的工程产出。

## 4. 难度控制（关键技巧）

真实 SAT 实例的难度不可控——随机 3SAT 在相变点（子句/变量比 ≈ 4.26）附近呈**重尾分布**，方差极大。直接用会导致出块时间剧烈波动。

**解法：把难度从 SAT 转移到哈希。**

> 一次「尝试」 = 生成一个实例 → 求解 → 检查 `H(instance‖assign) < TARGET`

- 单个实例耗时有方差，但**难度由 TARGET 控制**，与 SAT 硬度解耦
- 大数定律抹平方差 → 出块时间稳定
- 矿工可对超时实例 early-abort，这是所有人都能用的理性策略，**自动平衡**

**参数取值**（待标定）：实例规模应使**单次求解在毫秒级**，让每个区块包含大量尝试，方差才会被平均掉。

## 5. 与前两个方案的对比

| | NarrowNet | PoRT | **SAT-PoUW** |
|---|---|---|---|
| 反 GPU 手段 | 人为构造（FP64/串行/大内存池） | 网络延迟主导 | **问题天生如此** |
| 小机器优势来源 | 池子 ≥1GB | 缓存争用 + IP 配额 | 缓存争用（天然，**未实测**） |
| **验证成本** | ❌ 需完整重算 | ⚠️ ~640 ms | ✅ **O(n)，最优** |
| **工作有用吗** | ❌ 纯燃烧 | ❌ 纯燃烧 | ✅ **有真实产出** |
| 最大弱点 | 池子 <1GB 就输给 GPU | IP 配额机制有洞 | **算法优势导致中心化** |

## 6. ⚠️ 最大的问题：算法中心化

**这比前两个方案的任何弱点都严重，必须放在最显眼的位置。**

> 哈希类 PoW 中，所有人的最优算法相同，竞争发生在硬件层面。
> **SAT 求解不是——一个秘而不宣的、快 10 倍的求解器，就是 10 倍的挖矿优势。**

SAT 竞赛（SAT Competition）每年都有显著性能提升，掌握前沿技术的团队会获得实质优势，而**秘密算法比 ASIC 更隐蔽**——ASIC 至少还能买到。

**两种看法：**

- **悲观**：导致算法垄断，且不可见、不可购买、不可复制
- **乐观**：这恰恰是最有价值的部分 —— 为求解器研究提供持续经济激励，而技术一旦发表优势即消失

**缓解手段（都不彻底）：**

| 手段 | 效果 |
|---|---|
| 使用多样化实例族（不只随机 3SAT） | 单一技巧无法通吃，但强队仍占优 |
| 以公开求解器竞赛基准作参照，异常算力可被察觉 | 只能发现，不能阻止 |
| 接受它，并将「驱动求解器创新」写入项目叙事 | 转劣势为叙事 |

**这个取舍决定项目性质，需要设计者明确表态。**

## 7. 备选方案：格约减（SVP）

在高维格中寻找最短向量。

| | 表现 |
|---|---|
| 验证 | ✅ 检查向量属于格且范数足够小 —— 几乎瞬时 |
| 反 GPU | ✅ BKZ 约减串行且不规则 |
| 难度控制 | ✅ 由格维度精确控制，比 SAT 更可预测 |
| **真实价值** | ⭐ **所有后量子密码的安全性都建立在「格问题有多难」的估计上。一个持续攻击格挑战的全球网络，会产出真正有价值的安全参数数据。** |
| 缺点 | ❌ **题目供应有限**（挑战维度是固定的一组），效用层做不起来 |

**叙事更强**（"为后量子时代做安全体检"），**但可持续性弱于 SAT。**

## 8. 与现有 PoUW 项目的关系

| 项目 | 做法 | 与本方案的差异 |
|---|---|---|
| **Primecoin** | 寻找 Cunningham 素数链 | 同样满足「难求解易验证」，**是少数真正跑通的 PoUW**；但效用极窄（纯数论） |
| **Coin.AI** | DNN 训练 + 架构搜索 | 训练结果**难以廉价验证**，且 GPU 主场 |
| **Gridcoin / Curecoin** | BOINC 科学计算 | 验证依赖**中心化可信方**，非无信任 |
| **Filecoin** | 存储证明 | 有用且跑通，但奖励存储而非计算 |
| **本方案** | SAT 求解，两层结构 | 验证 O(n)，效用层与共识层解耦 |

## 9. 未验证清单（按重要性）

| # | 待验证 | 能否一票否决 | 方法 |
|---|---|---|---|
| **1** | **SAT 求解器的多线程扩展效率** | ✅ **能** | 用已有方法论（绑核 + 取最小值）跑开源求解器（MiniSat / CaDiCaL），测 1→N 线程退化曲线。**若扩展接近线性，小机器优势不成立，整条路砍掉** |
| 2 | GPU SAT 求解器的真实性能差距 | ✅ 能 | 文献调研 + 实测现有 GPU SAT 尝试 |
| 3 | 随机 3SAT 难度方差能否被大数定律抹平 | ⚠️ 影响参数 | 统计大量实例的求解耗时分布 |
| 4 | 效用层是否有真实需求与付费意愿 | ⚠️ 影响商业 | 市场调研 |
| 5 | 算法中心化的实际严重程度 | ⚠️ 影响设计 | 对比历年 SAT 竞赛冠军与基线求解器的性能差距 |

**实验 1 最便宜也最致命，应当最先做。**
